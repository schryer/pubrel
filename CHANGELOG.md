## 0.4.3 - 2026-10-08

Commit `3c975b576fb2`; release record `pub:sha2-256:lvoe5aibqydpyqkxh6qeyi5k5bdx36xjnudify3wuuluiuczwk4a`.

- A release may open with a summary: `pubrel summary TEXT` sets a paragraph for the next release, which `prepare` publishes as a signed `summary` claim and the changelog and GitHub release show above the list of changes.

## 0.4.2 - 2026-10-07

Commit `5ba28c0ecf2f`; release record `pub:sha2-256:s4jum2zqhzjsq3qxyiezd5ux3zl7lck2pf3b2cqso4pdcnlsgnma`.

### Added
- A crate whose release.json entry sets `"semver-checks": true` has its public API checked against its last release by cargo-semver-checks, in `check` and `prepare`: `changed` or `removed` allow a break, `added` an addition, and anything else no change. The release workflow installs the tool when given `semver-checks-version`.

## 0.4.1 - 2026-10-05

Commit `0fb8f054259e`; release record `pub:sha2-256:auupnlfuhd4jls72dsswnrj5534fnsmqlp7vzae6olm4qcp3qpiq`.

### Added
- release.json may declare security checks and facts. prepare runs the checks before releasing, refuses to release if one fails, and records each check's command, tool version and summary, and each fact, as a security claim signed with the release; the changelog and release notes list it, and check and tag refuse a release whose declared record is missing or unsigned.

## 0.4.0 - 2026-10-05

Commit `3997cb69934e`; release record `pub:sha2-256:raxwygjj2zzcymkbhtrh424vrmlmgsdl2efe7zner5wzr3jfv5xq`.

### Changed
- Versions follow Cargo's convention below 1.0.0: changed or removed bumps the minor version (0.3.1 to 0.4.0), and added, fixed or security bumps the patch version. From 1.0.0 the rules are as before. Versions are semver::Version, parsed strictly (no pre-release or build suffix), and the pub this drives must satisfy ^0.1 as Cargo reads it (at least 0.1.0, below 0.2.0).

## 0.3.0 - 2026-10-04

Commit `6173ec3e3a90`; release record `pub:sha2-256:v6wtc2hknnq2x7mprc3ja6sbycantm2c7wx5fx7ampiawapyseka`.

### Added
- release.json may list several `packages` -- a workspace and crates in it released with versions of their own -- each with its own unreleased list, package publet, changelog and tag prefix (`publet-core-v0.1.1`). add, next and prepare take --package; check, changelog and tag act on every package. A workspace bump leaves the pins of independently versioned crates alone, and their own releases pin their new versions in the workspace.
- A sixth change category, `internal`: a code change nothing users run sees (a refactor, a crate moved). It satisfies check, never bumps the version, and is listed in the next release something else makes.

## 0.2.0 - 2026-10-04

Commit `e3d0bcebc4bb`; release record `pub:sha2-256:kcmpa4wxncdzvbzyt7gdpczt25xzoxyvhidda76hchh7ei7ypmea`.

### Added
- check and tag verify that the package publet's identity and release claims carry a valid signature by the key release.json names (`key`, which init now records), and that every object they read hashes to its identifier; without `key` they warn instead.
- next, check, tag and changelog read the package publet in-process with publet-core, so only prepare needs pub. release.yml no longer installs pub (its pub-version input is accepted and ignored) and caches the pubrel it installs by version.

## 0.1.0 - 2026-10-04

Commit `16af33daa796`; release record `pub:sha2-256:t37ooqouiswnhe5mjojl7dsnhicfcfz456ayewr5njai42fzrbfa`.

### Added
- pubrel init, add, next, check, prepare, changelog, and tag: version a package by the categories of what changed and record each release as a version of its package publet.
- Manifest kinds cargo-workspace (with internal path dependencies), cargo-package, and pyproject.
- A reusable GitHub Actions workflow that checks pull requests against the release rules and tags published releases on main.
